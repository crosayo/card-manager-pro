### 2.2 エラー処理

| 関数 | 用途 |
|---|---|
| `handleSupabaseError(error, action)` | Supabaseのエラーを `Error`（`code` / `details` 付き）に変換して投げる。`42501` や RLS違反は「権限エラー」の文言に変換 |
| `isMissingFunction(error)` | RPC未登録の判定（`42883` または `PGRST202`）。未登録時のみフォールバック処理へ |
| `throwIfAnyFailed(results, action)` | 複数件の更新結果のうち1件でも失敗があれば例外化 |

主なエラーコード: `42P01`（テーブルなし）、`42883` / `PGRST202`（関数なし）、`42501`（権限なし）、`22023`（DB関数内の入力エラー。メッセージは日本語で利用者に表示可能）、`PGRST116`（該当行なし）。

画面側はトースト（`addToast`）で通知する。エラー詳細（`AppError`）を渡すとトーストからコピーできる。

### 3.2 DB関数・トリガー

| 名前 | 種別 | 権限 | 処理 |
|---|---|---|---|
| `normalize_search(text)` | SQL / immutable | — | NFKC → 空白・記号除去 → ひらがな→カタカナ → 小文字化（§5） |
| `search_items(...)` | plpgsql / invoker | 全員 | 検索・絞込・並替・ページング。戻り値 `{data, count}` |
| `increment_stock(item_id, delta)` | definer | **authenticated のみ**（関数内チェック＋anon実行権限なし） | 在庫を `greatest(0, stock+delta)` でアトミック更新 |
| `increment_supply_stock(p_supply_id, p_delta)` | invoker | RLSに従う | サプライ在庫のアトミック更新 |
| `reset_all_data()` | definer | **authenticated のみ** | items / products / news を全削除 |
| `get_dashboard_stats()` / `get_distinct_rarities()` | definer | 全員（読み取りのみ） | 集計 |
| `create_request(name, message, items jsonb)` | definer | 全員 | 本体＋明細を1トランザクションで登録し `{id, token}` を返す |
| `resolve_request_token(token)` | definer | 全員 | 受付中のリクエストIDを返す（無効・処理済みは null） |
| `edit_request_by_token(token, message, item_changes, remove_item_ids)` | definer | 全員（トークン照合） | メモ・枚数変更・明細削除と編集履歴の記録。全件削除は不可 |
| `swap_request_item_by_token(token, request_item_id, new_item_id)` | definer | 全員（トークン照合） | 同名カードの別バリアントへ差し替え |
| `handle_updated_at()` | トリガー | — | items の updated_at 更新 |
| `rotate_request_token_on_resolve()` | トリガー（`on_request_resolved`） | — | status が pending から変わったら token を入れ替え |
| `fetch_items_by_release_date(...)` | 旧関数 | — | **未使用**。`search_items` に置き換え済み。削除してよい |

> `definer`（SECURITY DEFINER）関数はRLSを迂回するため、**必ず関数内で権限・入力を検証すること**。新規追加時は `set search_path = public` を付ける。

## 4. セキュリティ設計

### 4.1 テーブル権限（2026-10-29 時点）

| テーブル | 未ログイン（anon） | 管理者（authenticated） |
|---|---|---|
| items / products / news / config / supplies / stock_logs | 閲覧のみ | 全操作 |
| requests | **列単位で閲覧のみ**（`token` 列は閲覧不可）。書き込み不可 | 全操作 |
| request_items / request_edit_logs | 閲覧のみ。書き込み不可 | 全操作 |

- 申請者の書き込みは DB関数（`create_request` / `edit_request_by_token` / `swap_request_item_by_token`）経由のみ。
- `requests` を anon で `select=*` すると権限エラーになるため、アプリは列を明示して取得する（`api.ts` の `REQUEST_PUBLIC_COLUMNS`）。

### 4.2 既知の注意点
- `config` は全員が閲覧できるため、**Discord Webhook URL も第三者から読める**（オーナー判断で現状維持）。
- `/api/scrape` は認証なしで任意URLを取得できる（[05 改善提案](05_改善提案とロードマップ.md) の最優先項目）。

## 5. 検索仕様

### 5.1 正規化規則（DB `normalize_search` と `utils.ts` の `toSearchKey` は同一規則）
1. Unicode NFKC 正規化（全角英数・半角カナ → 標準形）
2. 空白・ASCII記号・カード名に使われる記号（`《》「」『』【】・〈〉〔〕［］｛｝、。～〜―‐–—−･·☆★♪♡〝〟…`）を除去
3. ひらがな → カタカナ（`ぁ`〜`ゖ` を +0x60）
4. 小文字化

### 5.2 照合
- 検索ワードを空白（全角含む）で分割し、各語を正規化 → **すべての語が `search_key` に含まれる行**（AND検索）。
- `search_key` は「名前|型番|パック名」を `|` で連結しているため、語が項目をまたいで一致することはない。
- 例: 「ブラック マジシャン」「ぶらっくまじしゃん」「E-HERO」「dbss-jp036」「青眼 SM51」

### 5.3 並び替え（`p_sort_key`）
`releaseDate`（パックの発売日）/ `cardId` / `name` / `rarity`（`config.rarities` の順）/ `category` / `stock` / `updatedAt`、未指定は ID 降順。同順位は 型番 → レアリティ順 → ID。

### 5.4 変更時の注意
- 規則を変える場合は **DB関数と `toSearchKey` の両方**を変更し、`update public.items set name = name;` で全行の `search_key` を再計算する。
- 保存用の `normalizeForStorage` はひらがなを変換しない。**比較用の変換を保存経路で使わないこと**（過去にカード名をカタカナ化して壊した不具合の原因）。

## 6. 処理フロー

### 6.1 在庫の増減（連打対応）
1. 画面で即座に表示を更新し、増減数を `pendingDeltaRef` に積む。
2. 100ms 待って積み上がった増減数をまとめて `increment_stock` で送信。
3. 応答を待つ間のクリック分を加算して表示に反映（巻き戻り防止）。失敗時はサーバーから現在値を取り直す。
4. `stock_logs` に記録（失敗しても在庫操作は成功扱い）。

サプライも同じ方式（`increment_supply_stock`）。

### 6.2 リクエストのライフサイクル

```
[ゲスト] カートに追加 → 送信 ──create_request──▶ requests(pending) + request_items
                         ◀── {id, token}
          完了画面に編集用リンク /requests?token=… を表示・コピーを促す
          トークンを localStorage（card-manager:request-tokens）に保存

[ゲスト] 編集用リンクを開く ──resolve_request_token──▶ 受付中ならID（ブラウザに保存し、URLからは除去）
          編集 ──edit_request_by_token / swap_request_item_by_token──▶ 更新＋編集履歴

[管理者] 完了 ──requests.status=completed──▶ トリガーで token 入れ替え（申請者のリンクは無効）
          明細ごとに在庫を減算（カード: increment_stock / サプライ: increment_supply_stock）＋ stock_logs
[管理者] キャンセル ──status=cancelled──▶ token 入れ替え（在庫は変えない）
[管理者] 完了済みを編集 ──▶ 枚数差分・削除分・差し替え分を在庫へ戻す/減らす（note: 完了済みリクエストの編集）
```

在庫一覧には「受付中リクエストの枚数」（`fetchPendingQuantities`）を表示し、カートに入れられる上限は「在庫 − 受付中枚数」。

### 6.3 CSV在庫上書き
1. ヘッダー行から `ID` と `在庫数` の列位置を特定（列順に依存しない）。
2. 対象IDの現在在庫を取得し、変更がある行だけ更新。
3. 結果を「更新／変更なし／該当IDなし／不正な値／失敗」の件数で表示し、更新した行のみ増減数を `stock_logs`（source=csv）へ記録。

### 6.4 Wiki取込
1. `/api/scrape` が URL のHTMLを取得（文字コードは Content-Type、なければ EUC-JP）。
2. 本文領域の表、なければリストから「型番・カード名・レアリティ」を抽出。複数レアリティは行を分ける。
3. 画面で内容を編集し、既存カードと重複する場合は「在庫を加算／上書き／スキップ」を選んで登録。

## 9. コーディング規約（現行コードに合わせる）
- UI文言・コメント・コミットメッセージは日本語。
- TypeScript は camelCase、DB は snake_case。変換は `api.ts` の `mapDb…` 関数で行う。
- DBの失敗は握りつぶさず、利用者に分かる文言でトースト表示する。
- 改行コードは Git の `core.autocrlf=true`（作業ツリーは CRLF）。一括置換スクリプトを使う場合は改行コードに注意。
