# Card Manager Pro 改修ログ

改修のたびに **先頭（新しい順）** に追記する。コミット単位ではなく「1回の改修依頼」単位でまとめる。

## 記録ルール

```markdown
## YYYY-MM-DD 改修タイトル
- 依頼・背景: なぜ直したか（不具合の症状、要望）
- 変更内容: 何を変えたか（利用者から見た変化）
- DB変更: 実行したSQL（設定画面のSQLの番号、または ファイル名）。なければ「なし」
- 反映手順: SQLとデプロイの順番など、注意点
- コミット: `xxxxxxx`
- 確認: 実施した動作確認
```

> **DB変更がある改修は、必ず「DB変更」「反映手順」を書くこと。** アプリはGitの履歴から復元できるが、DBに何を実行したかはここにしか残らない。

## 2026-10-29 リクエスト編集の改善・カード名の修復
- 依頼・背景: リクエスト編集でカードを削除できない。完了後は申請者が操作できないようにしたい。過去の不具合でカタカナ化したカード名を直したい。
- 変更内容:
  - リクエスト編集画面にカードごとの削除（元に戻す可）を追加。全件削除は不可。
  - 完了・キャンセル時に編集用リンクを無効化。処理済みのリクエストは管理者のみ編集可。
  - 管理者が完了済みリクエストを編集すると、枚数差分・削除・差し替えを在庫へ自動反映。
  - リクエスト完了時にサプライ在庫が減らなかった不具合を修正。
  - カード名の修復: `backup_2026-04-04.json` を基準に519件、手動指定で33件（送り仮名・助詞をひらがなに戻す）。
- DB変更: 設定画面SQL 13-2（`resolve_request_token` を受付中のみに）、13-3（`edit_request_by_token` に `p_remove_item_ids` 追加。旧3引数版は削除）、14（トリガー `on_request_resolved`）。カード名修復のUPDATE（ファイルは実行後に削除）。
- 反映手順: **SQLを先に実行してからデプロイ**（新アプリは新しい引数を渡すため）。
- コミット: `ed8a5e8`
- 確認: 匿名キーで、修復後の名前・新関数の存在・無効トークンの拒否を確認。

## 2026-10-24 検索の刷新・セキュリティ修正・編集用リンク方式
- 依頼・背景: 正しい検索ワードでもヒットしない（ひらがなを含むカード名が発売日順で0件）。

  - リクエスト編集の本人確認を「名前の一致」から「編集用リンク（トークン）」に変更。バリアント差し替えの無認証、明細なしリクエストが残る問題も解消。
