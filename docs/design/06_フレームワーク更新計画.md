# Card Manager Pro フレームワーク更新計画（Node.js / React / Next.js）

| 項目 | 内容 |
|---|---|
| 版 | 1.0（2026-10-31 作成） |
| 目的 | サポートの切れた Next.js 14 系から脱却し、脆弱性の修正を受けられる状態にする |
| 進め方 | **1段階＝1回の作業（1つの会話・1つのブランチ）**。各段階の最後に必ずビルド・動作確認・コミットし、次の段階は新しい会話で始める |

---

## 1. 現状と目標

| 項目 | 現状（2026-10-31） | 目標 | 理由 |
|---|---|---|---|
| Node.js | 指定なし（ローカル 22.19、Vercel はプロジェクト設定に依存） | **24 LTS**（`engines` と Vercel の設定で固定） | 22 は 2027-04 にサポート終了。24 は 2028-04 まで |
| Next.js | 14.2.35（14系はサポート終了。修正されない脆弱性あり） | **16 系の最新安定版** | 脆弱性修正を受けるため |
| React | 18.3.1 | **19 系**（Next.js 16 が要求） | |
| TypeScript | 5.9.3 | 5.x のまま | 変更不要 |
| Tailwind CSS | 3.4.19 | 3.4 のまま | v4 は書き方が大きく変わるため今回は対象外 |
| supabase-js | 2.88.0 | 2.x の最新 | |
| lucide-react | 0.300.0 | 最新（React 19 対応版） | 0.300 は React 19 に未対応 |
| ESLint | 設定はあるがパッケージ未導入で動かない | 動く状態にする | |

### 1.1 先に片付ける不要ファイル（テンプレートの残骸）
| ファイル | 状態 | 対応 |
|---|---|---|
| `next.config.ts` | `next.config.mjs` と重複（14系では読まれない） | どちらか一方に統一 |
| `postcss.config.mjs` | 未導入の Tailwind v4 用。`postcss.config.js` と重複 | 削除 |
| `eslint.config.mjs` | 未導入の `eslint-config-next` を参照 | 段階4で導入 |
| `collect_code.js` / `full_project_code.txt` / `tsconfig.tsbuildinfo` / `package.json` の `cleanup` スクリプト | 移行作業の残骸と思われる | 内容を確認して削除 |

## 2. 計画表

| 段階 | 内容 | 主な作業 | 規模の目安 | 完了の条件 | 戻し方 |
|---|---|---|---|---|---|
| **0. 準備** | 安全に戻せる状態を作る | 作業ブランチ作成、設定画面でバックアップ取得、§3 の動作確認リストを一度通す | 小 | 確認リストが全て OK | — |
| **1. 整理と Node 24** | 足場を固める | §1.1 の不要ファイル整理、`package.json` に `"engines": {"node": ">=24"}`、`.nvmrc`、Vercel の Node.js Version を 24.x に変更 | 小 | ローカルと Vercel のプレビューでビルド成功 | コミットを戻す、Vercel の設定を戻す |
| **2. 周辺ライブラリの更新** | React 18 のまま更新できるものを先に | supabase-js・lucide-react・autoprefixer・postcss を最新へ。lucide-react のアイコン名の変更があれば修正 | 小〜中 | ビルド成功、アイコン表示の目視確認 | `package.json` と lock を戻す |
| **3. Next.js 15 + React 19** | 最大の山場 | `npx @next/codemod@latest upgrade` で 15 へ。React 19 / `@types/react` 19 へ。型エラー修正（`useRef` の引数必須化、`JSX` 名前空間など）。`next.config` の確認 | 中〜大 | ビルド成功、§3 の確認リスト全て OK | ブランチごと破棄 |
| **4. Next.js 16** | 最新へ | codemod で 16 へ。`next lint` 廃止に伴い ESLint CLI に移行（`eslint-config-next` 導入）。ビルドが Turbopack 既定になる点の確認 | 中 | ビルド・lint 成功、§3 全て OK | 段階3の状態に戻す |
| **5. 本番反映** | 公開 | Vercel のプレビューURLで最終確認 → `main` へ取り込み → 本番で確認。設計書（01・02）と改修ログを更新 | 小 | 本番で §3 全て OK | Vercel の「Instant Rollback」で直前のデプロイに戻す |

**段階3は、作業量が多ければ「3a: 15へ更新して型エラー以外を通す」「3b: 型エラー修正と確認」に分けてよい。**

## 4. 各段階の依頼文の例（新しい会話の最初に貼る）

> トークンを節約するため、毎回この設計書を読ませる。経緯の説明は不要。

```
C:\card-manager-pro-main\card-manager-pro-main で作業してください。
docs/design/06_フレームワーク更新計画.md の「段階1」を実施してください。
前提知識は docs/design/ の 01〜04 にあります（必要な部分だけ読んでください）。
完了したら §3 の確認リストのうち自動で確認できるものを確認し、作業ブランチにコミットしてください。
main への取り込みとプッシュは確認してから行ってください。
```

段階を変えるときは「段階1」の部分を変える。前の段階で問題が残っていれば、その内容を1〜2行で書き足す。

## 5. 注意点

| 項目 | 内容 |
|---|---|
| DB は変更しない | 本計画はアプリ側のみ。SQL の実行は発生しない想定 |
| Vercel の Node.js バージョン | プロジェクトの Settings → General → Node.js Version で変更する。`engines` だけでは反映されない場合がある |
| codemod の結果は必ず差分を確認 | 自動変換は誤ることがある。特に `next.config` と `layout.tsx` |
| Tailwind v4 / ESLint の大幅変更は混ぜない | 1回の変更範囲を小さく保つ。必要なら別計画にする |
| 失敗したら無理に直さない | その段階のブランチを破棄して原因をメモし、次の会話でやり直す |
