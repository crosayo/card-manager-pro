## 1. このシステムは何をするものか

遊戯王カードの**在庫管理システム（第1世代）**です。
現在の Card Manager Pro の原型となったシステムです。

```
主な機能一覧
┌─────────────────────────────────────────────────────┐
│  機能名           │  できること                        │
├─────────────────────────────────────────────────────┤
│  在庫一覧         │  カードの一覧表示・検索・絞込み    │
│  在庫増減         │  +1/-1ボタンで在庫数を変更         │
│  カード追加       │  新しいカードを手動で登録           │
│  カード編集       │  カード情報を修正                   │
│  カード削除       │  カードを削除（確認画面あり）       │
│  CSVエクスポート  │  在庫データをCSVでダウンロード      │
│  CSV取込み        │  CSVファイルから一括登録            │
│  Wikiスクレイパー │  遊戯王WikiからSeleniumで自動取込み │
│  製品管理         │  パック（製品）の追加・削除         │
│  レアリティ統一   │  表記ゆれを一括修正                 │
└─────────────────────────────────────────────────────┘

※ リクエスト管理・消耗品管理・ログ・ダッシュボードは未実装
```

## 6. リクエストの流れ（データフロー）

### 画面表示（在庫一覧）の流れ

```
ユーザーが "/" にアクセス
        │
        ▼
  main.py の index() 関数が呼ばれる
  （Springの @GetMapping("/") に相当）
        │
        ▼
  get_items_from_db() でSQLを組み立て
  ─────────────────────────────────────
  SELECT i.id, i.name, i.card_id, i.rare, i.stock, i.category,
         p.release_date, p.era
  FROM items i
  LEFT JOIN products p ON LOWER(TRIM(i.category)) = LOWER(TRIM(p.name))
  WHERE i.stock > 0  （条件によって変化）
  ORDER BY p.release_date DESC
  ─────────────────────────────────────
        │
        ▼
  Pythonでページネーション（件数を分割）
  all_items[start:end]
        │
        ▼
  render_template('main/index.html', items=...) でHTML生成
  （Springの return "index" + ModelAttribute に相当）
        │
        ▼
  Jinja2がHTMLに変数を埋め込む
  （Thymeleafの th:each="item : ${items}" に相当）
        │
        ▼
  ブラウザにHTMLを返す
```

### 在庫増減（+1/-1ボタン）の流れ

```
ユーザーが「+1」ボタンをクリック
        │
        ▼  JavaScriptで非同期送信（fetch API）
  POST /api/update_stock/<item_id>  へリクエスト
        │
        ▼
  main.py の api_update_stock() が実行
        │
        ▼  FOR UPDATEで行ロック（同時更新を防ぐ）
  SELECT stock FROM items WHERE id = ? FOR UPDATE
        │
        ▼
  UPDATE items SET stock = ? WHERE id = ?
        │
        ▼
  結果をJSONで返す
  {"success": true, "new_stock": 5}
        │
        ▼
  JavaScriptが在庫数の表示を更新
```

### Wikiスクレイピングの流れ

```
管理者がWikiのURLを入力して「取込み」ボタン押下
        │
        ▼
  POST /admin/wiki_import
        │
        ▼  Selenium でChromeブラウザを自動起動
  webdriver.Chrome() でブラウザ起動
  browser.get(url) でWikiページを開く
  WebDriverWait で読み込み完了を待機
        │
        ▼
  ページのHTMLを取得
  soup = BeautifulSoup(html, 'html.parser')
        │
        ▼
  テーブルを解析してカード情報を抽出
  （型番・カード名・レアリティ）
        │
        ▼
  結果をセッションに一時保存して確認画面へ
        │
        ▼
  管理者が確認して「登録」ボタン押下
        │
        ▼
  INSERT INTO items (...) VALUES (...) を繰り返し実行
```

## 7. 主要機能の詳細解説

### 7-1. Blueprint（モジュール分割）

FlaskのBlueprintはSpringの**パッケージ分割 + @RequestMapping** に相当します。

```
Blueprint の構造

  app/__init__.py（FlaskApp）
  ├─ app.register_blueprint(auth_bp)   → /auth/... のルート
  ├─ app.register_blueprint(main_bp)   → / のルート
  └─ app.register_blueprint(admin_bp)  → /admin/... のルート

  ※ Springで言うと
  @RequestMapping("/auth")  → auth.py
  @RequestMapping("/")      → main.py
  @RequestMapping("/admin") → admin.py
```

### 7-2. 認証の仕組み（users.json方式）

```
ユーザー情報は users.json ファイルに保存

  users.json の中身（例）:
  {
    "admin": "$2b$12$xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx（bcryptハッシュ）"
  }

  ログイン時:
    入力されたパスワード ──► bcryptハッシュ化 ──► jsonのハッシュと比較
    （werkzeug.security.check_password_hash を使用）

  ログイン後:
    session['username'] = 'admin'  ← HTTPセッション（Cookieベース）に保存
    ※ Springの HttpSession に相当

  認証チェック:
    @login_required デコレータ
    （Springの @PreAuthorize や Filter に相当）
    → g.user が None なら /auth/login にリダイレクト
```

### 7-3. DB接続方式

```
接続方法（毎回接続・毎回切断）

  def get_db_connection():
      conn = psycopg2.connect(DATABASE_URL)
      return conn                    ← 呼び出し元で使う

  ─── 使うたびに ───
  conn = db.get_db_connection()      ← 接続
  cur = conn.cursor()
  cur.execute("SELECT ...")          ← SQL実行
  result = cur.fetchall()            ← 結果取得
  conn.commit()                      ← コミット
  cur.close()                        ← カーソルを閉じる
  conn.close()                       ← 接続を閉じる

  ※ SpringのJdbcTemplate や try-with-resources に相当
  ※ コネクションプールは使っていない（単純な接続方式）
```

### 7-4. テンプレートエンジン（Jinja2）

```
Thymeleaf との比較

  Thymeleaf (Spring)              Jinja2 (Flask)
  ─────────────────               ──────────────
  th:each="item : ${items}"  →   {% for item in items %}
  th:text="${item.name}"     →   {{ item.name }}
  th:if="${condition}"       →   {% if condition %}
  th:href="@{/edit/{id}}"   →   {{ url_for('main.edit_item', id=item.id) }}
  layout:decorate="~{layout}"→   {% extends 'layout.html' %}
```

## 8. 認証の仕組み

```
旧システムの認証フロー

  ユーザーが /auth/login にアクセス
          │
          ▼
  ユーザー名 + パスワードを入力してPOST
          │
          ▼
  users.json を読み込む
          │
          ▼
  check_password_hash(stored_hash, input_password)
  で照合
          │
     成功 │           失敗
     ─────┼──────────────────
          ▼                  ▼
  session['username'] = 'admin'  エラーメッセージ表示
  ログインページへリダイレクト   （ログイン画面に戻る）

  以降のリクエスト:
  @login_required がついたURLは
    → g.user が None なら /auth/login にリダイレクト
    → g.user があれば処理続行
```

### 進化のポイント

```
【技術的な進化】

  旧: Selenium でChromeを起動してWikiを取得
      └─ Chromeのインストールが必要・重い・サーバー環境で動かしにくい
  新: HTMLを直接取得して文字列解析
      └─ ブラウザ不要・軽量・サーバーレス環境でも動く
```
