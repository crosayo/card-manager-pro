## 1. このシステムは何をするものか

遊戯王カードの**在庫管理システム**です。
個人利用 + 友人への共有を目的として作られています。

```
主な機能一覧
┌─────────────────────────────────────────────────────┐
│  機能名           │  できること                        │
├─────────────────────────────────────────────────────┤
│  ダッシュボード    │  在庫の全体集計を一目で確認         │
│  在庫管理         │  カードの在庫数を確認・増減          │
│  リクエスト       │  友人がカードを予約・申請できる      │
│  製品マスタ       │  パック（製品）の管理               │
│  消耗品管理       │  スリーブ・プレイマット等の管理      │
│  ログ             │  在庫の変更履歴を確認               │
│  スクレイパー     │  Wikiから自動でカード情報を取込み    │
│  設定             │  レアリティ・システム情報の管理      │
└─────────────────────────────────────────────────────┘
```

## 6. リクエストの流れ（データフロー）

### 通常の画面表示の流れ

```
ユーザーがブラウザで "/inventory" にアクセス
        │
        ▼
  Next.js がページを返す
  （inventory/page.tsx が実行される）
        │
        ▼
  AppContext（グローバル状態）からデータ取得
        │
        ▼
  api.ts の関数を呼び出す（例: api.fetchItems()）
        │
        ▼
  Supabase クライアントがDBにクエリを送信
  （JavaのJDBCテンプレートのようなもの）
        │
        ▼  HTTPSで通信
  Supabase（PostgreSQL）でSQL実行
  SELECT * FROM items WHERE ...
        │
        ▼
  結果がJSONで返ってくる
        │
        ▼
  mapDbItemToAppItem() でDB列名→アプリ用に変換
  （例: card_id → cardId, updated_at → updatedAt）
        │
        ▼
  画面にカード一覧が表示される
```

### 在庫更新（ボタンを押したとき）の流れ

```
ユーザーが「+1」ボタンをクリック
        │
        ▼
  api.updateStock(id, +1) を呼び出す
        │
        ▼
  Supabaseの RPC関数 "increment_stock" を呼び出す
  （JavaのストアドプロシージャのようなDB側の関数）
        │
        ▼  アトミックに（安全に）更新
  PostgreSQL で
  UPDATE items SET stock = stock + 1 WHERE id = ?
        │
        ▼
  更新後のデータが返ってくる
        │
        ▼
  画面の在庫数が更新される
  Toast（通知）が右下に表示される
```

### スクレイピングの流れ

```
管理者が WIKIのURLを入力して「取込み」ボタンをクリック
        │
        ▼
  ブラウザから /api/scrape に POST リクエスト送信
  （JavaのAjax通信に相当）
        │
        ▼
  api/scrape/route.ts（サーバー側）が実行される
  ※ここはブラウザでなくサーバー（Vercel）で動く
        │
        ▼
  Vercelサーバーが遊戯王WIKIにHTTPリクエスト
  EUC-JP → UTF-8 に文字コード変換
        │
        ▼
  HTMLを解析（パース）してカード情報を抽出
  ・型番（例: DUSA-JP001）
  ・カード名
  ・レアリティ（テキストから正規化）
        │
        ▼
  結果をJSON形式でブラウザに返す
        │
        ▼
  管理者が内容を確認して「DBに登録」ボタンを押す
        │
        ▼
  api.bulkInsertItems() で Supabase に一括登録
```

## 7. 主要機能の詳細解説

### 7-1. グローバル状態管理（AppContext）

Javaで言うと **Sessionスコープ** や **Singletonビーン** に相当します。
ログイン状態・製品一覧・レアリティ設定など、複数の画面で共通で使うデータを一か所で管理します。

```
AppContext が管理するデータ

  isAdmin     ログイン中かどうか（true/false）
  user        ログイン中のユーザー情報
  products    製品（パック）一覧
  rarities    レアリティ一覧（["UR", "SR", "R", "N", ...]）
  seasons     シーズン一覧
  news        お知らせ一覧
  toasts      画面に表示中の通知メッセージ一覧
```

```
データの流れ（コンテキストの仕組み）

  AppProvider（providers/AppContext.tsx）
  ├─ 全データを useState で保持
  ├─ AppShell（画面全体の枠）
  │   ├─ Sidebar（サイドバー）  ← isAdmin を参照して管理者メニュー表示
  │   └─ 各ページコンポーネント ← useAppContext() でデータを取得・使用
  └─ Toast（通知）              ← toasts を参照して通知を表示
```

### 7-2. 認証（ログイン）の仕組み

```
【ログインの流れ】

  /login 画面でメール・パスワード入力
          │
          ▼
  api.signInWithEmail(email, password) を呼び出す
          │
          ▼
  Supabase Auth が認証を行う
  （JWTトークンがブラウザに保存される）
          │
          ▼
  onAuthStateChange イベントが発火
  AppContext の isAdmin が true になる
          │
          ▼
  サイドバーに管理者メニューが表示される
  （スクレイパー・設定）

【ログアウトの流れ】

  ログアウトボタンクリック
          │
          ▼
  api.signOut() を呼び出す
          │
          ▼
  Supabase が JWTトークンを無効化
          │
          ▼
  isAdmin が false になる → 管理者メニューが非表示に
```

### 7-3. データの型定義（types.ts）

JavaのEntityクラスに相当します。データの「形」を決めます。

```typescript
// Item = カード在庫 1件のデータ形式（Javaで言うEntityクラス）
type Item = {
  id: number;        // PRIMARY KEY
  name: string;      // カード名
  cardId: string;    // 型番（例: DUSA-JP001）
  rarity: string;    // レアリティ
  stock: number;     // 在庫数
  category: string;  // 収録パック名
  updatedAt: string; // 最終更新日時
}
```

### 7-4. api.ts の設計

JavaのServiceクラスとRepositoryクラスを合わせたようなものです。
DB操作に関するすべての関数がここにまとまっています。

```
api.ts の関数一覧（カテゴリ別）

【認証】
  signInWithEmail()       メール・パスワードでログイン
  signOut()               ログアウト
  onAuthStateChange()     ログイン状態の変化を監視

【製品マスタ（products）】
  fetchProducts()         一覧取得
  addProduct()            新規追加
  updateProduct()         更新
  deleteProduct()         削除

【カード在庫（items）】
  fetchItems()            ページネーション付き一覧取得
  fetchItemById()         1件取得
  addItem()               新規追加
  updateItem()            更新（名前・レアリティ等）
  updateStock()           在庫数の増減（RPC使用）
  deleteItem()            削除
  bulkInsertItems()       CSVや取込みデータを一括登録

【リクエスト（requests）】
  fetchRequests()         一覧取得（ステータスでフィルタ可）
  createRequest()         新規作成
  updateRequestStatus()   完了・キャンセル処理
  editRequest()           内容を編集
  deleteRequest()         削除

【ログ（stock_logs）】
  fetchStockLogs()        在庫変更履歴を取得
  addStockLog()           ログを記録

【設定（config）】
  fetchRarities()         レアリティ一覧取得
  saveRarities()          レアリティ一覧保存
  fetchSeasons()          シーズン一覧取得
  fetchSystemInfo()       システム情報取得

【その他】
  fetchDashboardStats()   ダッシュボード用集計（RPC使用）
  sendDiscordNotification() Discord通知送信
  resetDatabase()         全データ削除（RPC使用）
```

### 7-5. ページネーション（大量データの分割取得）

```
例: 在庫が5000件ある場合

  一度に全件取得すると重い
          │
          ▼
  1ページ = 50件 に分割して取得

  ブラウザ → Supabase
    SELECT * FROM items
    LIMIT 50 OFFSET 0     ← 1ページ目（1〜50件）
    LIMIT 50 OFFSET 50    ← 2ページ目（51〜100件）
    ...

  JavaのSpring Dataの Pageable に相当する仕組み
```

### 7-6. RPC関数（DB側のストアドプロシージャ）

パフォーマンスが必要な処理はDB側（PostgreSQL）の関数として定義されています。

```
使用中のRPC関数一覧

  increment_stock(item_id, delta)
    └─ 在庫を安全に増減（同時に複数人が更新しても正しく動く）

  fetch_items_by_release_date(p_direction, p_page, ...)
    └─ 発売日順のソート+ページネーション（高速）

  get_dashboard_stats()
    └─ ダッシュボードの統計（合計カード数・在庫数・在庫切れ数）

  get_distinct_rarities()
    └─ DBに存在するレアリティの種類一覧を取得

  reset_all_data()
    └─ 全データを削除（初期化）
```

## 8. 認証・権限の仕組み

```
ユーザー種別と権限

  【非ログインユーザー（友人）】
  ├─ 在庫一覧を見る     ○
  ├─ リクエストを送る   ○（名前を入力して申請）
  ├─ スクレイパーを使う ×
  └─ 設定を変更する     ×

  【管理者（ログイン済み）】
  ├─ 在庫一覧を見る     ○
  ├─ 在庫を増減する     ○
  ├─ リクエストを処理する ○
  ├─ スクレイパーを使う ○
  └─ 設定を変更する     ○
```

### DBレベルのセキュリティ（Row Level Security）

SupabaseはPostgreSQLの **RLS（行レベルセキュリティ）** を使っています。
Oracleの**VPD（Virtual Private Database）** に相当します。

```
例: items テーブルのRLSポリシー

  誰でも読める（SELECT）     ← 在庫一覧は公開
  書き込みは認証済みのみ     ← 在庫変更は管理者のみ

  JWTトークンを持っていれば → 書き込み可能
  JWTトークンがない場合   → 読み取りのみ
```
